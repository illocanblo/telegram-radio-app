# Интеграция с archive.org

Документ описывает, как приложение взаимодействует с archive.org: какие endpoint'ы используются, как обрабатываются данные, какие оптимизации применены и какие ограничения есть у текущей реализации.

Все обращения к archive.org идут **напрямую из браузера** — CORS разрешён сервисом, прокси не нужен.

---

## Используемые endpoint'ы

### 1. Поиск каталога — advancedsearch.php

**Функция:** `loadLibrary()` в `src/App.jsx`.

URL: `https://archive.org/advancedsearch.php?q=(uploader:"..." OR uploader:"...") AND mediatype:"audio"`

**Параметры:**
- **Фильтр:** список почт аплоадеров лейбла (`UPLOADER_EMAILS`) — три адреса, объединённые через `OR`
- **Поля:** `identifier`, `title`, `creator`, `date`, `publicdate`, `mediatype`
- **Сортировка:** по `publicdate desc`
- **Лимит:** 300 релизов за запрос
- **Формат:** JSON

**Результат:** массив облегчённых записей (без файлов), который кэшируется в `localStorage` как `nr.library.v1` и используется для грида карточек.

**Особенность:** каталог грузится одним запросом при старте приложения и обновляется только кнопкой «Обновить каталог» в тулбаре.

---

### 2. Метаданные релиза — metadata/{identifier}

**Функция:** `fetchAlbum(id)` в `src/App.jsx`.

URL: `https://archive.org/metadata/{identifier}`

Возвращает полную структуру объекта: `metadata` (title, creator, date, description, subject) и `files` (список всех файлов в элементе с размером, форматом, длительностью).

Из этого строятся:

**`buildTracks(data, id)`** — выбирает только аудиофайлы (`mp3`, `ogg`, `opus`, `m4a`, `aac`, `flac`, `shn`), применяет дедупликацию по имени файла (без расширения) с приоритетом по `FORMAT_RANK`: лучший формат одного трека побеждает худший. Треки сортируются по имени с учётом чисел.

**`findZip(data, id)`** — ищет готовый `.zip` в самом элементе (некоторые релизы уже содержат его). Если есть — используется для скачивания.

**`cleanDescription(raw)`** — чистит HTML из описания: удаляет теги, декодирует сущности, схлопывает пустые строки.

---

### 3. Обложки — services/img/{identifier}

URL: `https://archive.org/services/img/{identifier}`

Готовый PNG от сервиса, без необходимости парсить файлы элемента. Используется:
- в карточках каталога (`<Cover>` с `loading="lazy"`)
- на странице релиза (большая обложка + размытый фон `hero-bg`)
- в плеере (`p-cover-btn`)
- как источник для публикации в историю Telegram

При ошибке загрузки компонент `Cover` показывает цветной fallback с инициалами и хеш-оттенком (`hashHue(seed)`), чтобы карточки не были «дырявыми».

---

### 4. Аудиофайлы — download/{identifier}/{filename}

**Конструктор:** `fileUrl(id, name)`.

URL: `https://archive.org/download/{identifier}/{filename}`

Файлы именуются в archive.org иногда с подпапками — имена кодируются через `encodeURIComponent` с сохранением слешей между сегментами пути.

**Куда попадают ссылки:**
- в очередь воспроизведения (`queue`)
- в плеер через `<audio src={current?.url}>`
- в кнопку «Скачать трек» (только после прослушивания, см. `played.has(track.key)`)
- в Telegram `downloadFile()` или внешнюю ссылку

**Аудио-элемент** использует `preload="metadata"` — не качает трек целиком до старта воспроизведения, а только заголовки. Буфер (`buffered`) отображается в виде отдельной полоски на seekbar.

---

### 5. Архивирование — compress/{identifier}

**Конструктор:** `compressUrl(id, formats)`.

URL (два варианта):
- `https://archive.org/compress/{identifier}` — весь элемент
- `https://archive.org/compress/{identifier}/formats=FLAC,MP3` — только указанные форматы

Это штатный endpoint archive.org, который собирает ZIP на лету на стороне сервера.

**Логика выбора в `downloadAlbum()`:**
1. Если в метаданных найден готовый `.zip` (`findZip`) — используется он (точнее и быстрее)
2. Иначе — `compressUrl(id, formats)` с перечнем форматов треков релиза
3. Перед загрузкой показывается нативный `confirmNative` с предупреждением о возможном времени сборки
4. Результат уходит в Telegram через `downloadFile()` или открывается во внешнем браузере

---

### 6. Внешняя страница — details/{identifier}

URL: `https://archive.org/details/{identifier}`

Открывается в подвале страницы релиза через `openExternal(url, instantView=true)` — с попыткой открыть в Telegram Instant View, если доступно. Это единственный способ «провалиться» в оригинальный элемент archive.org, где видны комментарии, рецензии, полные теги.

## Кэширование и оптимизация

### Три уровня кэша метаданных

**1. Память** — `metaCache` (`Map` в `useRef`): живёт пока открыта вкладка.

**2. sessionStorage** — `storeMeta(id, built)`: 6 часов TTL (`META_TTL`), максимум 40 ключей с LRU-вытеснением через индекс `nr.meta.idx`. Версия помечается `META_VER`, при её изменении старые записи игнорируются.

**3. Запрос в полёте** — `inflight` (`Map`): если один и тот же релиз запрошен дважды, возвращается тот же промис.

### Предзагрузка

- **IntersectionObserver** на карточках каталога (через `data-album`) — при появлении в видимой области добавляет id в prefetch-очередь
- **Hover/focus/touch** на карточке — приоритетный prefetch
- **При автопереключении релиза** (`nextAlbumAuto`) — предзагрузка следующего в том же направлении

**Ограничения:**
- `PREFETCH_CONCURRENCY = 2`
- максимум 6 авто-предзагрузок (`PREFETCH_AUTO_MAX`)
- пропускается при `navigator.connection.saveData` или `2g`

### Мгновенная оболочка

При открытии релиза сначала рисуется **shell** (`shellFor(id)`) — из данных каталога: обложка, название, артист, год. Треклист показывается скелетоном. Когда `fetchAlbum` возвращается — shell заменяется на полные данные. Благодаря этому **никогда не показывается предыдущий открытый релиз**.

### Токен запроса и отмена

`reqToken` в `useRef` инкрементируется при каждом `loadInto`. Ответ, пришедший после того, как пользователь уже ушёл на другой релиз, отбрасывается. `AbortController` с `FETCH_TIMEOUT = 12000` обрывает запрос при таймауте.

## Ограничения текущей интеграции

| Ограничение | Последствие |
|---|---|
| Нет авторизации — только публичные элементы | Нельзя работать с приватным контентом |
| Rate limit со стороны archive.org (не документирован явно) | При массовом prefetch может быть 429; в коде не обрабатывается |
| `advancedsearch.php` возвращает до 300 записей | Если каталог вырастет — нужна пагинация (`page`, `rows`) |
| Длительность трека берётся из `file.length` как строка | Парсится вручную (`parseLength`), может ломаться на нестандартных форматах |
| Описание в HTML-формате | `cleanDescription` убирает всё — ссылки и разметку в описаниях теряются |
| `compress` собирается на лету | Большие релизы (500+ МБ) могут собираться десятки секунд или падать с таймаутом |

## Возможные улучшения

### Пагинация поиска
Если каталог перевалит за 300 релизов — добавить параметры `page` и `rows` в запрос к `advancedsearch.php`.

### Поиск по описанию и тегам
Сейчас `advancedsearch` возвращает только `title/creator/date`, поиск по `description` требует отдельного запроса `q=(description:"..." OR ...)`.

### Поддержка коллекций
Сейчас фильтруется только по `mediatype:"audio"`, но лейбл может иметь коллекции с обложками/текстами, которые сейчас не попадают в каталог.

### Индекс по формату
Фильтры «только FLAC», «только MP3» на уровне каталога потребуют хранить `formats` в карточках каталога (сейчас их нет в `advancedsearch`-ответе).

### Проксирование через Vercel Edge Function
Если захочется скрыть домен archive.org от пользователя или добавить кеширование на стороне сервера.
